# Deployment

Target: **Render, region Frankfurt (EU)**, defined in [`render.yaml`](../render.yaml)
(ADR 0011). **Nothing is deployed yet.** The Docker image is portable (Fly.io, Railway, a VPS).

## Components

| Render resource | Purpose | Plan (start) |
| --- | --- | --- |
| `bartoszup` web service | `Dockerfile` target `prod`: gunicorn + WhiteNoise | Starter |
| `bartoszup-db` | PostgreSQL 17, daily backups | Basic 256 MB |
| `bartoszup-expire-listings` cron | `manage.py expire_listings` at 03:15 UTC | Starter |

Migrations run in `preDeployCommand` on every deploy. The reference-data fixture is loaded **once**
(step 4 below): it uses fixed primary keys, so re-loading it would overwrite edits made by
moderators in the admin.

## First deploy checklist

1. Render dashboard → **New → Blueprint** → select the GitHub repo. Render reads `render.yaml`.
2. Fill the `sync: false` variables:
   - `EMAIL_URL`: SMTP of an **EU** provider, e.g.
     `smtp+tls://USER:PASSWORD@smtp.example.eu:587`
   - `DEFAULT_FROM_EMAIL`: e.g. `BartoszUP <no-reply@your-domain.pl>` (domain with SPF/DKIM)
   - `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`: Google Cloud Console → OAuth client (Web),
     redirect URI `https://<domain>/konto/google/login/callback/`
   - `DJANGO_ADMIN_EMAILS`: comma-separated, receive error emails
3. After adding a custom domain, update `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS`
   and `SITE_URL`, then change the Site domain in `/admin/sites/site/`.
4. Render shell: `python manage.py loaddata reference_data`, then
   `python manage.py createsuperuser`.
5. Smoke test: `/healthz/`, signup + email verification, create and publish a listing,
   send an inquiry, `/sitemap.xml`.

## Environment variables

See [`.env.example`](../.env.example). Production-specific:

| Variable | Default | Notes |
| --- | --- | --- |
| `DJANGO_SETTINGS_MODULE` | `config.settings.prod` | set in the image |
| `DJANGO_SECRET_KEY` | – | generated by Render |
| `DATABASE_URL` | – | from the Render database |
| `DJANGO_SECURE_SSL_REDIRECT` | `true` | Render terminates TLS and sets `X-Forwarded-Proto` |
| `DJANGO_SECURE_HSTS_SECONDS` | 30 days | raise to 1 year once stable |
| `DJANGO_SECURE_HSTS_PRELOAD` | `false` | enable only deliberately |
| `WEB_CONCURRENCY` | `3` | gunicorn workers |
| `LISTING_DEFAULT_LIFETIME_DAYS` | `60` | |

## GDPR / RODO notes for operations

- Keep all resources (web, database, backups, email provider, future object storage, error
  tracking) in the EU/EEA; sign data processing agreements (DPA) with each provider.
- Do not copy production data to local machines; use `seed_demo` for realistic test data.
- Inquiries contain personal data; define a retention period (e.g. delete after 12 months).
- See ADR 0009 and the roadmap for Phase 3 (health data) requirements.

## Building the production image locally

```bash
docker build --target prod -t bartoszup:prod .
docker run --rm -p 8001:8000 \
  -e DJANGO_SECRET_KEY=local -e DJANGO_ALLOWED_HOSTS=localhost -e DJANGO_SECURE_SSL_REDIRECT=false \
  -e DATABASE_URL=postgres://bartoszup:bartoszup@host.docker.internal:5432/bartoszup \
  bartoszup:prod
```
